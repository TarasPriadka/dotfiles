# Fresh-context pilot evaluations

Run these from the dotfiles checkout with the default framework installed through
`skills/install.sh`. Keep
the configured model unchanged when comparing instruction revisions. Each
`codex exec` below creates a fresh session; do not use `resume` or `fork` for the
continuation test. The worker sees ordinary task prompts, not evaluator expectations
or the conversation that developed the framework.

## Check discovery and proportional effort

In a new empty temporary directory, ask Codex without tool use to identify the
personal guide already in its initial instructions. Check the saved session's
initial messages as well as the response; the guide heading is “Working with Taras.”
Then use a separate fresh session for:

> In two sentences, what's the difference between a requirement and an implementation choice?

A useful answer should remain short and should not create a work record or load
the full engineering workflow. The guide is a default expectation, not a mandate
to run every activity on every request.

## Investigate, hand off, and implement

The fixture is a small stdlib-only Python cache cleanup library and CLI. Copy
only the fixture into the worker's workspace. Keep prompts, evaluator checks,
and output logs outside that workspace:

```sh
trial_root="$(mktemp -d)"
cp -R agents/evals/fixture "$trial_root/workspace"
codex exec --skip-git-repo-check --sandbox workspace-write --json \
  -C "$trial_root/workspace" -o "$trial_root/design-answer.md" - \
  < agents/evals/investigate-prompt.txt > "$trial_root/design-events.jsonl"
```

Inspect the result before the next step. The agent should independently load
`engineering-work`, investigate the actual flow, preserve the design-only scope,
and leave a useful `.agent-work/.../work.md` handoff. Compare the original files
to the fixture: application code, tests, and README should remain unchanged.
Ignore generated bytecode when comparing; no semantic edit is authorized here.

Start a different session against the same workspace:

```sh
codex exec --skip-git-repo-check --sandbox workspace-write --json \
  -C "$trial_root/workspace" -o "$trial_root/implementation-answer.md" - \
  < agents/evals/continue-prompt.txt > "$trial_root/implementation-events.jsonl"
PYTHONDONTWRITEBYTECODE=1 python3 agents/evals/check_dry_run.py "$trial_root/workspace"
```

The continuation prompt supplies implementation authorization, not prior reasoning.
The agent should recover and reconcile the saved model, implement the change, run
relevant checks, update the record, and keep everything local. Inspect its changes
and final explanation as well as the independent checker. No commits or publication
are requested. The checker intentionally remains outside the task context and tests
public API/CLI outcomes, including exact byte preservation in preview mode.

## Evaluate and iterate

Use a fresh fixture for a rerun of investigation. Record guide, skill, and record-
guidance hashes; model and reasoning configuration; session IDs; latency and usage
reported by the runner; and material user interventions. Report cumulative input
and cached input separately; they are not unique context size or billable cost.

Judge selection, the usefulness of the work, scope discipline, and continuity.
Avoid scoring the presence of preferred headings or ownership language. A shorter
record is useful only if it still carries decisions, evidence, limits, and the next
action. When a refinement changes the handoff, test continuation from that handoff
if its adequacy is uncertain. Stop repeating tests once the relevant concern is
resolved or clearly documented as a limitation.

These are functional smoke trials, not a controlled demonstration that the
framework improves model capability. Broader tasks and a comparison condition
are needed to assess reliability and return on time/tokens.
